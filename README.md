# Sucya-Asma

**Preserving wisdom. Inspiring generations.**

Sucya-Asma is a small, growing studio for culturally respectful, source-aware animated storytelling. The current creative foundation is a Ramayana-inspired series with Rama and Hanuman character bibles and a pilot story about the squirrel and Rama’s bridge. The long-term goal is to automate repeatable production work while keeping research judgment, cultural care, creative approval, and final release under human direction.

## Start here

1. Read [the project vision](docs/VISION.md) and [the production workflow](docs/PRODUCTION_WORKFLOW.md).
2. See the staged [roadmap](docs/ROADMAP.md), [toolset choices](docs/TOOLSET.md), [production roles](docs/PRODUCTION_ROLES.md), and [automation plan](docs/AUTOMATION_ARCHITECTURE.md).
3. Follow the [zero-budget and continuity policy](docs/COST_AND_CONTINUITY_POLICY.md) before enabling any hosted service or moving into production.
4. Follow [the character workflow](docs/CHARACTER_WORKFLOW.md) before generating production scenes.
5. Use the existing [Rama](universe/character-bibles/ramayana/rama.md) and [Hanuman](universe/character-bibles/ramayana/hanuman.md) bibles as drafts; approved snapshots are versioned separately.
6. Review the pilot folder at `stories/development/the-squirrel-and-ramas-bridge/`. It is framed as a Ramayana-associated traditional narrative, not a direct passage from the Valmiki Ramayana. Its source review needs inspectable citations before public release.
7. Use [books-to-knowledge](docs/BOOK_TO_KNOWLEDGE.md) to build a cited knowledge base; reading or ingesting books does not automatically train a reliable historical model.

## Current status

- **Stage:** foundations and pre-production design.
- **Existing assets:** Rama/Hanuman character drafts, partial director/agent specifications, templates, and squirrel-and-bridge pilot materials. Several agent, director, character, and pilot files remain empty placeholders; see the roadmap before treating them as usable.
- **Not yet established:** complete cited source ledger, final character reference sheets, production automation code, tool installation verification, release cadence, and final storage layout.
- **Important:** repository documentation is planning material unless it contains sources readers can inspect. An `APPROVED` label alone does not prove a source review or image evaluation is complete.

## Principles

- Label the source tradition and evidence status of each story and claim.
- Distinguish epic text, historical evidence, living tradition, interpretation, and dramatization.
- Preserve citations and asset/model license information through the final export.
- Build one small complete episode before scaling into a series.
- Keep working files, generated assets, and final delivery organized and reproducible.
- Agents draft and check; a human approves source framing, story, canon, final cut, and release.

## Working rule

GitHub stores versioned documentation and source code. Drive is the proposed active workspace; MEGA can hold a second archive copy of larger files. Do not commit copyrighted books, large media, model files, credentials, or private data. See [tool and storage choices](docs/TOOLSET.md).
