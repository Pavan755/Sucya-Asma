# Character-first production workflow

The repository already has draft and approved-version files for Rama and Hanuman, with separate performance and motion documents. Build on these without conflating a bible with one prompt or generated image. The bible describes canon; reference sheets demonstrate it; performance and motion libraries guide portrayal; approval snapshots lock a version.

## Character stages

1. **Source and tradition notes:** identify texts, translations, visual traditions, regional variation and dates. Do not present one modern image as the only authentic representation.
2. **Narrative function:** define role, relationships, goals, values, limits, development, and what the character should not be reduced to.
3. **Core identity bible:** silhouette, face, age range, build, skin/fur/feathers, hair, costume/materials, objects/symbols, emotional center, boundaries, and sources for design choices. Mark interpretation separately.
4. **Performance library:** voice, emotional range, posture, gestures, listening behavior, dialogue rhythm, relationships, and prohibited caricatures. Record pronunciation/language notes.
5. **Motion library:** walk/run, stillness, turns, action, gesture timing, camera interaction, and physical limits.
6. **Visual reference pack:** neutral turnaround, three-quarter view, expression sheet, costume/prop sheet, scale chart, and lighting/color tests. Label each with bible version and provenance.
7. **Continuity test:** create stills in different scenes/lighting. Compare face, proportions, costume, markings and symbols. Fix the bible before animating.
8. **Approval/version lock:** record version, date, files, notes, and permitted variation. Major identity change becomes a new version; prior work stays linked to its source version.
9. **Episode use:** director references the approved bible and specifies visible traits per shot. Character agent can flag deviation, not rewrite canon.

## Start with existing characters

- Audit Rama and Hanuman bibles, performance/motion docs, reference evaluation and approval snapshots together. Check contradictions and missing fields/dates. An `APPROVED` label does not prove all images or evaluations exist.
- Choose a production approach (2D cutout, illustrated motion, 3D, or mixed) only after checking hardware and tools. Make one approved static character pack before animation.
- Treat the squirrel in the pilot as a supporting character; make a compact bible if it recurs or needs continuity. Don't let mascot design dictate cultural meaning.
- Create one bridge/coastal environment pack from story research and storyboard, labeling geography and period assumptions.

## Continuity checklist

- Face/proportions match approved version.
- Costume, props, markings, colors, symbols have a source or design rationale.
- Expression and body language match performance library.
- Camera/lighting does not alter identity cues.
- Cultural symbols are used intentionally and consistently.
- Prompt, references, model/checkpoint, output and approval are linked in the asset manifest.
- New evidence or interpretation is logged before canon changes.

## Files needed for a production-ready character

`character-bible.md`, `performance.md`, `motion.md`, `sources.md`, labeled `references/`, `continuity-checks.md`, `approval.md`, and an asset manifest. Use `templates/character-bible-template.md` as a starting point.
