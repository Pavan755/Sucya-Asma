# Books to knowledge base

Start with reading and cited notes, not the assumption that ingesting books trains a reliable history model.

## Intake

For each source, create a Zotero item and ledger row: author/editor/translator, exact title/edition, publisher/year, ISBN or stable URL, language, source type, access date, rights/usage notes, and questions it may inform. Assign `SRC-###` consistently across Zotero, notes and ledgers.

Keep each copy in an authorized location. Do not upload, share, or send a purchased/copyrighted book to Drive, MEGA, or an external model unless the rights and provider terms allow it. Public-domain status of an old text does not automatically make a modern translation public domain.

## Read and extract

1. Define the question before reading.
2. Read relevant sections and write page-precise summaries; quote only what is lawful and needed.
3. Tag notes by person, place, event, claim, tradition, and episode. Preserve author uncertainty and edition/translation.
4. Add claims with exact page references and source limitations. No source is authoritative for every question.
5. Seek corroboration and differing traditions/interpretations.
6. Flag unresolved claims for a human editor. Agent drafts must include page references; no fabricated citations.
7. Use approved notes as retrieval material for story, character, environment, and director agents.

## Safe automation path

First automate metadata cleanup and ledger validation. Later, if rights permit, use local OCR/text extraction and require human verification of pages and quotations. Keep extracted text out of Git. Test retrieval on questions with known page answers before using it in production.

## Learning record

Maintain a human-reviewed topic brief: question, source list, key cited claims, disagreements, confidence/limits, unknowns, and review date. This is the project knowledge base, not a claim of permanent AI training.
